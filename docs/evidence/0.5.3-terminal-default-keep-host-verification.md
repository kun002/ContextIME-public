# ContextIME 0.5.3 Terminal 默认 KEEP 主机验证

## 结论

`0.5.3-preview` 已在主开发机已登录、解锁的 Windows console Session 1 完成覆盖升级和交互桌面验证。独立 Windows Terminal 聚焦后不再被 Context Service 强制切到英文；普通拼音、手动中英文切换和项目候选链保持正常。

```text
CONTEXTIME_0_5_3_TERMINAL_DEFAULT_KEEP = VERIFIED
```

该结论只覆盖独立 Windows Terminal。VS Code integrated terminal 的 `KEEP` 已实现并通过原生单元/CI 门禁，但本轮没有完成真实 integrated-terminal UI 输入，因此仍为 `REAL_WINDOWS_VERIFICATION_REQUIRED`。

## 覆盖升级与运行时

主机从 `0.5.2-preview` 覆盖升级到 `0.5.3-preview`，未重启系统即完成以下验证：

- 卸载项版本和路径已指向 `C:\Program Files\ContextIME\contextime-0.5.3-preview`；
- ContextIME `WeaselServer.exe` 与 `contextime-context-service.exe` 均在 Session 1 从 0.5.3 安装目录运行；
- 官方小狼毫 `C:\Program Files\Rime\weasel-0.17.4\WeaselServer.exe` 同时运行；
- ContextIME IME Pipe、Context Service Pipe、Project Indexer Pipe 和 Project Candidate Pipe 全部存在；
- 官方 Weasel Pipe 同时存在。

因此本机本次覆盖升级后无需重启即可使用。首次安装、重启后持久性和卸载仍未由本轮重新验证。

class PlayerController {

第一次调用错误地沿用了 baseline 默认期望“输入法”，而 fixture 只产生 `PlayerController` 和 `spawnPlayer`，因此等待不存在的 symbol 超时。词典和 Adapter 日志证明当次产品链路已成功写入两个真实 symbols。改用固定场景的正确参数 `player → PlayerController` 后一次通过；没有为重试修改产品代码。

两次 smoke 创建的项目词典均已通过 Context Service 的 `CIPM REMOVE_PROJECT` 管理协议删除，没有直接删除文件。既有真实项目词典仍存在，SHA-256 保持：
